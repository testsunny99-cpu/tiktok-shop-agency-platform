# 关键决策

## 2026-11-11 — 以机构多账号为第一性对象

- 状态：accepted
- 决策：系统按账号池、授权关系和批量任务设计，不按单账号脚本设计。
- 原因：机构需要同时管理很多创作者账号；不同账号的授权、区域、配额和风险状态互不相同。
- 影响：数据模型必须有 account_id；任务必须可拆分到账号级；Token 不可共享。

## 2026-11-11 — Creator 与 Seller/Shop 分离

- 状态：accepted
- 决策：Creator API 和 Seller API 不共用账号模型的业务权限；允许同一机构同时接入两类账号。
- 原因：创作者发布带货视频使用 creator scope 和 creator access token；卖家授权用于店铺、商品和合作相关能力。
- 影响：UI、权限、Token、错误处理和审计均需标明账号类型。

## 2026-11-11 — 凭证移出业务文档

- 状态：accepted
- 决策：App Secret、Token 和授权码只放在 `.env.local` 或正式密钥管理系统；Git 仅保留 `.env.example`。
- 原因：原始资料含真实 App Secret，文档化时必须避免继续扩散。
- 影响：本地可继续接入，但任何提交前都必须检查 `git diff` 和 `git ls-files`。

## 2026-11-11 — 先做 API 工作流验证，再确定技术栈

- 状态：accepted
- 决策：MVP 先验证授权、签名、上传、预检、发布和状态机的端到端流程，再决定数据库、队列和部署方案。
- 原因：区域、应用类别、scope、配额和视频接口可用性是当前最大不确定性。
