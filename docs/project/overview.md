# 项目概览

## 目的

把 TSP 机构的多账号带货视频运营从人工登录、表格登记和零散脚本，变成集中、可批量执行、可暂停、可重试、可审计的运营系统。

## 核心问题

- 机构账号数量多，账号授权、区域、店铺和权限状态难以维护。
- 每个创作者必须使用自己的授权上下文，不能用机构主账号 Token 代替。
- 视频发布包含上传、商品关联、预检、提交和异步状态，人工流程容易重复或漏发。
- API 配额、账号风控、Token 过期和网络失败会让批量任务出现部分成功。
- 机构需要知道“哪个账号、哪个视频、哪个商品、何时、由谁、以什么结果”完成了发布。

## 目标用户与工作场景

| 用户 | 主要任务 |
|---|---|
| 机构管理员 | 接入账号、查看授权和风险状态、配置权限 |
| 运营人员 | 选择账号和商品，建立批量视频任务，查看进度 |
| 内容团队 | 提供符合规范的视频资产和商品映射 |
| 技术管理员 | 配置应用、Webhook、队列、限流、审计和故障恢复 |

## 成功标准

- 多个账号可独立授权并显示 Token/权限/区域状态。
- 一次批量任务可拆分为账号级子任务，支持并发上限、暂停、重试和部分成功。
- 每个发布子任务都有幂等键和最终状态，重复执行不会无意重复发帖。
- 运营人员能看到失败原因、配额/风控提示和下一步动作。
- 凭证不出现在 Git、普通日志、前端或截图中。

## 价值边界

平台帮助机构高效、合规地使用 TikTok Shop 已开放的授权和内容发布能力；不会代替 TikTok 完成创作者审核，也不会承诺突破平台配额或风控。
